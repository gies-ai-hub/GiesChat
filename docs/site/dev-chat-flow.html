Life of a chat message

What happens between a student pressing Send on "Explain WACC for BADM 449" and the streamed answer appearing, and which file owns each step.

sequenceDiagram
  participant C as Browser (ChatForm)
  participant R as /api/agents/chat
  participant J as GenerationJobManager
  participant A as Agents run (LangGraph)
  participant M as Azure OpenAI · GPT-6 Luna
  C->>R: POST message (JWT)
  R->>R: moderation · PII filter · agent ACL
  R->>J: start background job, returns streamId
  C->>J: GET /stream/:streamId (SSE)
  J->>A: createRun(agent, tools, files)
  A->>M: Responses API (web search, reasoning)
  M-->>A: token deltas
  A-->>J: events
  J-->>C: SSE deltas, message renders

Step by step

  1. Client submits. client/src/components/Chat/Input/ChatForm.tsx → useSubmitMessage → ask() in client/src/hooks/Chat/useChatFunctions.ts, which sets the submission.
  2. Client opens the stream. client/src/hooks/SSE/useAdaptiveSSE.ts picks useResumableSSE: POST to start, then subscribe with GET /api/agents/chat/stream/:streamId. Events are handled by useEventHandlers, useStepHandler and useContentHandler.
  3. Middleware chain. api/server/routes/agents/chat.js runs resume context, the PII filter, moderation, agent access and resource ACL, conversation access, then buildEndpointOption, all before anything reaches a model.
  4. Background job. api/server/controllers/agents/request.js runs the generation as a job in packages/api/src/stream/GenerationJobManager.ts. The job outlives the HTTP request, so a dropped tab can reconnect (useResumeOnLoad).
  5. Agent setup. packages/api/src/agents/initialize.ts loads the agent, its tools, MCP servers and files. api/server/services/Endpoints/agents/initialize.js builds the AgentClient.
  6. Run. packages/api/src/agents/run.ts resolves the provider (getProviderConfig) and calls Run.create from @librechat/agents, which is LangGraph-based. Tool calls such as document search and MCP tools happen inside this loop.
  7. Stream back and save. Deltas flow through the job manager (in memory, or Redis with USE_REDIS) to the SSE stream. Messages are saved to MongoDB, token usage is recorded (usage.ts, transactions.ts) and a title is generated with gpt-5.4-mini.
Gotcha: plain model chats (no agent picked) still go through the agents pipeline as an ephemeral agent. There is no separate "simple chat" path, so debugging a plain GPT-6 chat means reading the agents code.

Embed chats

An embedded chat uses exactly this flow. The difference is the user: an embed guest whose JWT only allows their one agent (see Auth & permissions), with its own rate limiter (api/server/middleware/limiters/embedLimiter.js).
