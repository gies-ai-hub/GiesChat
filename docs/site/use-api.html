Agent API

Let your own course site talk to one of your class agents. Students sign in with Illinois on your site, and your site's server calls GiesChat for them.

Sign-in required. Anyone can read this page, but using the API needs a GiesChat account. You sign in to GiesChat to create a key, and every call must carry the token of a student who signed in with Illinois.

API or embed?

  • Embed puts a ready-made GiesChat chat box on a Canvas page or web page. No code needed. See Embedding an agent.
  • The API is for a site with its own server and its own chat screen. You write the code that sends each message and shows the reply.

What you need

  • An agent you built in the Agent dashboard. You must be its author or a co-admin.
  • A site with a server. The key is a secret: keep it on the server, never in browser code.
  • Illinois sign-in on that site: a Microsoft Entra app registration in the University of Illinois directory, the same one GiesChat signs in with.

1. Set up Illinois sign-in on your site

Register your site as an app in Microsoft Entra and add Illinois sign-in with any standard library (for example MSAL). Then:

  • Ask for the scopes openid profile email. GiesChat needs the oid claim, which Microsoft only includes with profile.
  • Use the v2.0 sign-in endpoint (the default in current libraries).
  • Note the app's Application (client) ID. You need it in the next step.

After a student signs in, your library gives you their ID token. That is what you send to GiesChat. ID tokens expire after about an hour, so get a fresh one when it runs out.

2. Create a key

In the Agent dashboard, hover your agent and choose the key icon (API access). Choose New key, then enter:

  • Key name: for you, for example the site it is for.
  • Site's Entra app ID: the Application (client) ID from step 1. The key only accepts student tokens issued to that app.

3. Call the API

The API follows the OpenAI format, so the OpenAI SDKs work with it. Base URL:

https://gieschat.azurewebsites.net/api/agents/v1

Every call sends two headers:

HeaderValue
AuthorizationBearer <your key>
X-GiesChat-User-TokenThe signed-in student's Illinois ID token

Python (Responses API)

from openai import OpenAI

client = OpenAI(
    base_url="https://gieschat.azurewebsites.net/api/agents/v1",
    api_key=GIESCHAT_KEY,  # from your server's settings
)

first = client.responses.create(
    model="agent_abc123",  # your agent's id, or an allowed model (see below)
    input="When is the midterm?",
    extra_headers={"X-GiesChat-User-Token": student_id_token},
)
print(first.output_text)

# Continue the same conversation
follow_up = client.responses.create(
    model="agent_abc123",
    input="What does it cover?",
    previous_response_id=first.id,
    extra_headers={"X-GiesChat-User-Token": student_id_token},
)

curl (Chat Completions)

curl https://gieschat.azurewebsites.net/api/agents/v1/chat/completions \
  -H "Authorization: Bearer $GIESCHAT_KEY" \
  -H "X-GiesChat-User-Token: $STUDENT_ID_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "When is the midterm?"}]}'

The reply's X-GiesChat-Conversation-Id header holds the conversation id (non-streaming replies also carry it as conversation_id). Send it back as conversation_id to continue. Add "stream": true for a streamed reply.

Conversations

  • Send only the student's new message. GiesChat keeps the history, and it uses only the last user message you send. system and assistant messages are ignored.
  • A key can only continue conversations it started.
  • Students see these chats in their own GiesChat sidebar, tagged with the key's name, and can carry on there.
  • The chats count in your dashboard. Use the Source filter to see API traffic alone, or one key.

Choosing a model

Leave model out, or set it to your agent's id, to use the model you picked in the builder. To use another model for one call, send its id. GET /models lists the models you can pick. A key works with its own agent only, so another agent's id is refused.

Limits

  • 300 calls a minute per key.
  • 20 calls a minute per student, per key.
  • Over a limit, GiesChat answers 429 with a Retry-After header in seconds.
  • Tools that connect to other services (Canvas, Outlook and so on) are off for API calls. The agent answers from its instructions and documents.

Errors

Errors use the OpenAI shape: {"error": {"message", "type", "code"}}.

StatusCodeWhat to do
401invalid_user_tokenThe student token is missing, expired, or was issued to a different app than the key's. Get a fresh ID token, and check the key's app ID.
401invalid_api_keyThe key's agent was deleted. Create a key on another agent.
403key_wrong_agentmodel named another agent. Use your agent's id, a model id, or leave it out.
404model_not_foundThat model isn't offered. Pick one from GET /models.
404conversation_not_foundThe conversation id is wrong, or another key started it. Start a new conversation.
429rate_limit_exceededWait for the number of seconds in Retry-After.

A revoked or unknown key is refused too.

Turning it off

Open API access again and choose Revoke next to the key. It stops working right away. Deleting the agent also deletes its keys.
