Auth & permissions

Who you are comes from Illinois Entra ID. What you can do comes from four layers: role, system grants, per-resource ACLs and, for embed guests, a single allowed agent.

Signing in

flowchart LR
  U[User] -->|Sign in with Illinois| E[Entra ID / OpenID]
  E --> S[api/strategies/openidStrategy.js]
  S -->|claim pending invites, sync roles| DB[(user, aclEntry)]
  S --> T[access JWT 15 min + refresh cookie 7 days]
  • OpenID (Entra) in api/strategies/openidStrategy.js is the real login path. Gies added two things to it: syncing roles from claims (OPENID_REQUIRED_ROLE, OPENID_ADMIN_ROLE) and claiming pending agent invites on sign-in, which turns pendingCollaborators/pendingCoAdmins emails into user ids.
  • Sessions: a short-lived access JWT (SESSION_EXPIRY) plus a refresh-token cookie (REFRESH_TOKEN_EXPIRY), stored in the session and token collections and checked by api/server/middleware/requireJwtAuth.js.
  • Guest auto-login (GIESCHAT_GUEST_LOGIN): refreshController creates a guest user through getOrCreateGuestUser() in api/server/services/AuthService.js. A gieschat_logged_out cookie stops it from logging someone straight back in.
  • Local, LDAP, SAML and the social strategies still exist from upstream but are mostly off.

Embed guests

packages/api/src/embed/session.ts mints a guest user per visitor, pinned to one agent (user.embedAgentId), with a 1-day token. requireJwtAuth then rejects any request from that user that isn't about their agent. For "Illinois accounts only" embeds, the session returns no token until the visitor signs in through the popup.

Rule of thumb: never gate an action on createdVia or other UI hints on the agent. Access is always the ACL plus grants.
