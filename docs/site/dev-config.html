Configuration

Two files drive the running app: librechat.yaml (what the app offers) and .env (secrets and URLs, never committed).

How config loads

librechat.yaml is baked into the Docker image, so changing it means a deploy. At startup packages/api/src/app/ loads it and validates it against the schema in packages/data-provider/src/config.ts. A typo fails validation at boot, not later. In the YAML, ${VAR} pulls a value from .env, and {{VAR}} is filled in per user (e.g. a student's own Canvas token).

Models

The agents endpoint allows two providers: the custom Azure OpenAI endpoint (Responses API, web search, medium reasoning) and Anthropic (ANTHROPIC_API_KEY). What users see in the picker comes from modelSpecs:

Every spec shares the Gies baseline prompt: short answers, no emojis, bold headings only, academic integrity. Titles are generated with gpt-5.4-mini.

Retiring a model: remove its modelSpecs entry and add its id to RETIRED_MODELS in client/src/utils/endpoints.ts, but keep it in the endpoint's models list. Agents are validated against that list, so agents still pinned to the old model would fail. Retired models stay hidden from every picker except on an agent that still uses one, so it can move off. Give it a FALLBACK_GUIDE label in ModelCards.tsx so it doesn't show as a raw id. The class-dashboard default lives in DASHBOARD_MODEL in client/src/components/Admin/Dashboard.tsx.
